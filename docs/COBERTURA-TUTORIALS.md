# Format i cobertura funcional dels tutorials

Totes les fitxes de `_content/tutorials/` comparteixen exactament les mateixes metadades obligatòries i en el mateix ordre (`title`, `description`, `robot`, `level`, `duration`, `order`, `image`), així com els huit apartats comuns i en el mateix ordre: repte i objectius, materials i preparació, funcions del robot treballades, seqüència guiada, prova i reflexió, accessibilitat i seguretat, evidències d’aprenentatge, i fonts oficials i límits. Cada repte comença amb una introducció i una llista d’objectius; materials, funcions, preguntes i evidències també són llistes. La seqüència és un conjunt de passos numerats consecutivament que es mostra amb el mateix wizard; la quantitat de passos pot variar amb l’abast de cada pràctica, però no la plantilla ni la navegació. La secció de prova descriu sempre una comprovació observable abans de les preguntes, que han de referir-se a la funció treballada i no a una pregunta genèrica. Les imatges i els blocs de codi s’intercalen dins dels apartats pertinents, sense crear una estructura alternativa.

La cobertura és una propietat del conjunt de tutorials de cada robot, no cal que cada fitxa explique totes les funcions. Una funció només es considera coberta quan apareix en una seqüència guiada que es pot executar o provar, té una comprovació observable i n’explica els límits de maquinari o versió. Els accessoris o extensions que no formen part del kit base s’identifiquen com a opcionals. La prova `_scripts/test-tutorial-format.js` valida metadades, ordre dels apartats, numeració, preguntes, renderització al wizard i presència de pràctiques guiades per a l’inventari de funcions de cada robot.

Les 36 fitxes segueixen la plantilla i navegació comunes. La cobertura es considera per robot i només compta quan una pràctica guiada prova la funció i n’explica els límits. `_scripts/test-tutorial-format.js` comprova les metadades i apartats exactes, que cada pas arribe al wizard, que les preguntes siguen específiques i que hi haja un protocol observable; també contrasta l’inventari mínim de capacitats amb els passos guiats del corpus. La verificació final de compatibilitat s’ha de fer amb els models, accessoris i versions de programari de cada centre. Les integracions que necessiten serveis en línia queden identificades com a dependències externes, no com a capacitats autònomes del maquinari.
